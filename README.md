# שלא תדעו

אתר סטטי בעברית להתארגנות מעשית אחרי מוות של אדם קרוב: הלוויה, שבעה, שלושים וגילוי מצבה, ומה צריך להסדיר אחרי הפטירה.

- **בעלים:** רני שגיא ובן זוגה. הקוד, התוכן, מאגר GitHub והדומיין שייכים להם.
- **תחזוקה:** Claude. הבעלים כותבים מה לשנות, Claude עורך, בודק ומפרסם.
- **אין שרת, אין מסד נתונים, אין חשבונות משתמשים ואין כלי סטטיסטיקה.** התקדמות בצ׳קליסטים נשמרת רק בדפדפן של המבקר.

## איך מבקשים שינוי (בלי לגעת בקוד)

פותחים שיחה עם Claude בתיקייה של הפרויקט וכותבים בפשטות מה לשנות, למשל:

> בעמוד השבעה, בסעיף "כיבוד וארוחות", תוסיף משפט...
> הקישור לחברת החשמל לא עובד, תבדוק ותתקן.
> תוסיף משימה לצ׳קליסט הבירוקרטיה: ...

Claude אמור:
1. לערוך את הקובץ המתאים ב-`content/`.
2. להריץ `npm test`.
3. לרשום ב-`CHANGELOG.md` מה השתנה, איך נבדק והאם צריך לפרסם מחדש.
4. לפרסם, כלומר לבצע commit ו-push ל-`main`. GitHub בודק ומפרסם אוטומטית.

**כלל חשוב:** כל שינוי מהותי בניסוח מאושר, בפרט אישי או בעובדה מקצועית מוצג קודם לאישור של רני.

### תחביר מיוחד בקובצי התוכן

- `:::links` … `:::`: רשימת קישורים רשמיים מתחת לפסקה. `:::links featured` מציג אותה בהדגשה.
- `:::note` … `:::`: מסגרת "מהניסיון שלי".
- `:::checklist levaya` / `:::tasks` / `:::download`: מקומות שבהם מוצגים הצ׳קליסטים והורדת התבנית.
- `:::pending` … `:::`: טקסט שעדיין ממתין לאישור. מוצג באתר עם תווית "טיוטה". כשהטקסט מאושר מסירים את השורות `:::pending` ו-`:::`.

## שמירת הצ׳קליסטים: מה חשוב לדעת

- הנתונים נשמרים ב-`localStorage` במפתח `shelo-tedu`, עם מספר גרסה (`version`).
- **לכל משימה יש מזהה קבוע (`id`)**. לשינוי ניסוח משנים רק את `text`. אסור לשנות או למחזר `id`, כי ההתקדמות של אנשים שמורה לפיו.
- הוספת משימה: מוסיפים שורה עם `id` חדש. אצל מי שכבר התחיל, היא תופיע כ"טרם טופל".
- הסרת משימה: אם מישהו כבר כתב עליה הערה או עדכן סטטוס, המידע לא נמחק. הוא מוצג בנפרד תחת "משימות ששמרתם בעבר", ונכלל בייצוא ובגיבוי.
- אם בעתיד ישתנה מבנה הנתונים, מעלים את `SCHEMA_VERSION` ב-`store.js` ומוסיפים שלב המרה ב-`migrate()`, עם בדיקה.
- מגבלות שמוסברות למשתמשים: השמירה היא רק בדפדפן ובמכשיר הזה, בלי סנכרון בין מכשירים, וניקוי נתונים או גלישה פרטית עלולים למחוק אותה. לכן יש ייצוא ל-CSV, קובץ גיבוי ושחזור.

## הרצה ובדיקות (למי שעובד עם הקוד)

דרוש Node.js 20 ומעלה.

```bash
npm install
npx playwright install chromium
npm run dev          # בנייה ותצוגה ב-http://localhost:8080
npm test             # בנייה + בדיקות יחידה + בדיקות דפדפן (נייד ומחשב)
npm run check:links  # בדיקת הקישורים החיצוניים (gov.il חוסם בדיקה אוטומטית, ולכן קישורים שלו בודקים ידנית)
npm run test:browsers  # בדיקות הדפדפן גם על Safari (WebKit). דורש: npx playwright install webkit
```

מה נבדק אוטומטית:
- כל פסקה במסמך התוכן המאושר מופיעה באתר מילה במילה (`tests/unit/content-fidelity.test.mjs`).
- שמירה, עדכוני גרסה, נתונים פגומים, ייצוא, גיבוי ושחזור (`tests/unit/store.test.mjs`).
- בדיקות דפדפן בנייד ובמחשב (`e2e/site.spec.mjs`):
  - כל העמודים, RTL, בלי גלילה אופקית
  - קישורים פנימיים ועמוד 404
  - נגישות אוטומטית (axe, WCAG 2.2 AA)
  - הורדת התבנית
  - הצ׳קליסטים: רענון, סינון, משימה אישית, מחיקה באישור, CSV, גיבוי ושחזור, עדכון גרסה
  - מצב בלי JavaScript ומצב שבו localStorage חסום
  - בדיקה שההערות לא נשלחות לשום שרת

## פרסום

- המאגר: `ramportu1999/shelo-tedu` ב-GitHub. הוא ציבורי, כלומר כולם יכולים לקרוא אבל רק הבעלים יכולים לשנות.
- כל push ל-`main` מריץ את `.github/workflows/deploy.yml`: הוא מריץ בדיקות ובונה, ורק אם הכול עובר הוא מפרסם ל-GitHub Pages.
- הכתובת הזמנית: `https://ramportu1999.github.io/shelo-tedu/`.
- **מעבר לדומיין משלכם:**
  1. רוכשים דומיין.
  2. ב-GitHub נכנסים ל-Settings → Pages → Custom domain ומגדירים אותו.
  3. אצל רשם הדומיין מגדירים רשומות DNS לפי ההוראות של GitHub.
  4. מעדכנים את `siteUrl` ב-`content/site.json`.
  5. ב-Settings → Variables מגדירים משתנה `BASE_PATH` עם הערך `/`.
- **עלות:** האירוח ב-GitHub Pages חינמי. ההוצאה היחידה הצפויה היא הדומיין.
